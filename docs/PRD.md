# PolyMind 产品需求文档（PRD）

版本 V0.1 ｜ 状态：立项 ｜ 目标发布：MVP 内测

---

## 1. 背景与问题

2025—2026 年，桌面 Agent 从「聊天框」进化成「能动手的工作台」：字节 Trae 改名 Trae Work、阿里把通义灵码长成 Qoder 系列、腾讯从 CodeBuddy 扩到 WorkBuddy。它们解决了"Agent 能不能干活"，但也留下三个结构性缺口：

1. **模型被套餐绑架**：三家都用积分制，用户无法选择"这个任务用便宜模型、那个任务用旗舰模型"，更无法接自己的私有网关或本地模型。
2. **数据与密钥要过第三方**：企业代码、内部文档、API Key 都在厂商云端，合规团队过不了审。
3. **过程不可审计**：Agent 改了什么、跑了什么命令，多数产品只给一段自然语言总结，没有可追溯的本地账本。

同时，开源侧（Cline、Continue、OpenClaw 类）证明了"BYOK + 本地执行"有真实需求，但普遍是 IDE 插件或极客脚本，缺少一个**面向非纯工程用户的独立桌面客户端**：能装、能点、能审批、能看账单。

## 2. 产品定位

**一句话**：一个 Bring-Your-Own-Key 的桌面智能体工作台，把"选模型、给权限、看花费"三件事交还给用户。

**不是什么**：
- 不是代码编辑器（不替代 VS Code / JetBrains）；
- 不是模型聚合聊天站（不做多模型并排闲聊）；
- 不是云 Agent（不托管执行环境，任务只在本机跑）。

**差异化的三条护城河**：

| 维度 | 同类做法 | PolyMind 做法 |
| --- | --- | --- |
| 商业模型 | 订阅 + 积分，平台转售 token | 软件免费，用户直连上游，平台零抽成 |
| 权限模型 | 目录一次性授权 / 无审批 | 路径牢笼 + 命令白名单 + 分级审批 + 审计表 |
| 能力扩展 | 平台审核的插件市场 | MCP 标准协议，用户自己接任意 server |

## 3. 目标用户

| 用户 | 场景 | 关键诉求 |
| --- | --- | --- |
| 独立开发者 / 学生 | 改课程项目、跑脚本、整理笔记 | 便宜、能用国产模型、不想买会员 |
| 小团队技术负责人 | 让 Agent 在受控目录里做重构、写测试 | 可审计、可限制命令、能接内部网关 |
| 数据/运营同学 | 批量整理文件、生成报告、抓网页 | 门槛低、有审批不怕误删 |
| 隐私敏感行业 | 代码不能出内网 | 本地模型（Ollama）+ 本地执行 |

**非目标用户**：需要多人协作、云端定时任务、移动端的人群（V2 之后再说）。

## 4. 范围

### P0（V0.1，本期必须）

1. 供应商管理：新增/编辑/删除，Key 加密存储，连通性测试，模型列表拉取。
2. 三类协议适配：OpenAI 兼容、Anthropic、Gemini；覆盖 Azure 与 Ollama。
3. 流式对话：逐 token 展示，展示思考过程（若上游返回），展示 token 与成本。
4. Agent 工具循环：6 个内置工具，最多 16 步，工具结果回灌。
5. 权限门：路径越界拒绝、命令白名单、三级审批、本会话放行。
6. 会话持久化：SQLite 保存消息，可重命名/删除/导出 Markdown。
7. MCP：stdio 接入、工具发现、调用，工具名空间隔离。
8. 用量账本：按模型聚合请求数、token、成本。
9. 上下文预算：超限折叠早期消息，保留工具调用配对完整。
10. 兜底模型链：主模型失败自动切换，并在界面提示。

### P1（V0.2）

- 图片/截图输入（视觉模型）；
- 工作区文件树与 diff 预览（改前确认）；
- 会话内搜索、按项目分组；
- 命令执行前的 dry-run 预览；
- 供应商级限流与并发队列。

### P2（V0.3+）

- 子代理（Sub-agent）与任务分解；
- 定时任务 / 触发器；
- 团队共享的只读策略模板；
- 远程 MCP（SSE / streamable HTTP）；
- 可选云端同步（端到端加密）。

### 明确不做

- 代码补全与 LSP（不做第二个 IDE）；
- 平台代售 token；
- 未经审批的自动批量删除 / 格式化；
- 把用户密钥上传到自家服务器。

## 5. 关键用户旅程

### 5.1 首次配置（目标 < 3 分钟）

打开应用 → 空状态引导 → 设置 → 添加供应商（选协议、填 URL/Key/模型）→ 测试连通 → 回主界面选模型 → 发第一句话。
**失败兜底**：测试失败时给出分类错误（鉴权 / 网络 / 模型不存在），而不是一句 "请求失败"。

### 5.2 一次典型任务

用户："把 `src/utils/date.ts` 里的 moment 换掉，改成 date-fns，然后跑测试。"

1. Agent 先 `fs_grep` 找引用 → `fs_read` 读文件；
2. 说明改动点 → `fs_write` 触发**审批弹窗**（展示目标路径、字节数、风险等级）；
3. 用户允许 → 写入完成事件流上屏；
4. `run_command`（`npm test`）触发**高风险审批**（展示完整命令与工作目录）；
5. 失败则读 stderr 再修，最多两步；
6. 结束给出结论 + 本轮成本。

### 5.3 换模型

同一个会话里，顶栏下拉从 `deepseek/deepseek-chat` 切到 `claude/claude-sonnet-4-5`，历史上下文不丢，下一轮用新模型。
计价按各自单价，账本按 `provider/model` 分列。

## 6. 功能细则（验收口径）

| 编号 | 需求 | 验收标准 |
| --- | --- | --- |
| F-01 | 供应商 CRUD | 保存后重启应用仍存在；Key 字段在配置文件里不可读 |
| F-02 | 连通性测试 | 401 → 明确提示"Key 无效"；超时 → 提示网络问题；成功展示延迟与模型数 |
| F-03 | 流式输出 | 首 token P50 < 1.5s（不含模型自身延迟）；中断后不残留半条消息 |
| F-04 | 工具审批 | 拒绝后该工具不执行，Agent 收到"用户拒绝"并调整策略 |
| F-05 | 路径牢笼 | `../`、绝对路径越界、符号链接逃逸三类用例全部拒绝 |
| F-06 | 命令白名单 | 非白名单程序直接拒绝；参数不经 shell，`;` `|` 不产生注入 |
| F-07 | 会话导出 | 导出 Markdown 含用户/助手/工具结果三段，代码块完整 |
| F-08 | 用量账本 | 单会话与全局聚合一致，误差 < 1e-6 美元 |
| F-09 | MCP | 服务启动失败不影响主流程，仅在 MCP 面板提示 |
| F-10 | 上下文预算 | 超预算后仍能完成当前轮工具调用，不出现孤立 tool 消息 |

## 7. 非功能需求

- **性能**：冷启动 < 3s；空会话内存 < 120MB；1k 条消息会话滚动 60fps。
- **安全**：密钥不出本机；默认拒绝未知命令；所有写操作可审计。
- **可观测**：本地日志分级（error/warn/info/debug），不默认记录 prompt 全文。
- **兼容**：Windows 10+、macOS 12+、Ubuntu 22.04+（AppImage）；模型协议向后兼容。
- **可用性**：单供应商故障时，有兜底模型则任务不中断；无兜底则明确报错并保留已生成内容。

## 8. 成功指标（内测 4 周）

| 指标 | 目标 |
| --- | --- |
| 首次配置完成率 | ≥ 70% |
| 首日产生 ≥ 1 次工具调用的用户占比 | ≥ 45% |
| 任务完成率（用户未中途停止且无报错） | ≥ 65% |
| 审批拒绝率 | ≤ 15%（过高说明工具选择策略有问题） |
| 单任务平均成本（混合模型） | < $0.03 |
| 崩溃率 | < 0.5% 会话 |

## 9. 风险与对策

| 风险 | 影响 | 对策 |
| --- | --- | --- |
| 上游协议差异导致工具调用失败 | 高 | 适配器单测覆盖三种协议的 tool call 往返；错误可重试判定 |
| 提示注入诱导越权 | 高 | 权限由内核判定，模型无法修改白名单；路径 canonicalize |
| 用户不会配 Base URL | 中 | 供应商预设模板 + 一键填入（DeepSeek/豆包/通义/Moonshot/Ollama） |
| 上下文爆掉 | 中 | 预算折叠 + 工具输出截断 + 单轮步数上限 |
| 密钥文件被拷走 | 中 | AEAD 加密 + 文件权限；V0.2 接 Windows DPAPI / macOS Keychain |
| 竞品免费额度冲击 | 中 | 不打价格战，打"可控 + 可审计 + 可自托管" |

## 10. 依赖与里程碑

- M1（2 周）：内核 + CLI 跑通三类供应商；
- M2（2 周）：Tauri 外壳 + 审批 + 存储；
- M3（2 周）：MCP + 用量 + 导出；
- M4（1 周）：内测包、崩溃与日志、文档。

**发布门槛**：`cargo test` 全绿、`tsc --noEmit` 零错误、三条供应商真实 key 各跑通一次带工具的会话。
